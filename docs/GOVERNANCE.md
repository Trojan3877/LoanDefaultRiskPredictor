# Credit-Risk Governance Boundaries

Software controls support—but do not replace—model-risk and lending governance.

Before lending use, bind each artifact to an inventory record, accountable owner, intended population/use, data lineage and permissible purpose, validation report, threshold policy, approved reason-code mapping, approval status, expiration/revalidation date, monitoring plan, incident contacts, and decommission procedure.

Protected attributes used for legally reviewed fairness analysis must remain segregated from predictive features and production request telemetry. Retention, deletion, access, encryption, consent, adverse-action, and audit requirements must be defined by qualified reviewers for the target jurisdiction and institution.

Generated language must not be the authoritative adverse-action reason. Only deterministic, model-faithful, versioned, policy-approved reason codes may enter a controlled notice workflow.
